# Архитектура

## Цели

- Единый API для регистрации серверов и приёма телеметрии (heartbeat + метрики)
- Надёжное хранение в Postgres
- Возможность развития до полноценного мониторинга (алёрты, интеграции, дашборды)

## Компоненты

- **API (`backend/`)**
  - FastAPI + OpenAPI (Swagger)
  - SQLAlchemy 2.0 (ORM)
  - Alembic (миграции)
  - Авторизация по API ключу (MVP; позже JWT/OAuth2 + RBAC)
- **UI (`/ui`)**
  - Встроенная HTML-панель (без отдельного фронтенда)
  - Страницы: список серверов и статус heartbeat, детали сервера, алёрт-правила, алёрты, генератор конфига для агента
  - По умолчанию UI открыт, но может быть защищён API ключом через `UI_REQUIRE_API_KEY`
- **База данных**
  - Postgres (таблицы: `servers`, `heartbeats`, `metric_points`, `alert_rules`, `alert_events`)
  - Индексы по времени и ключам (`server_id`, `name`, `ts`)
- **Agent (`agent/`)**
  - Отправляет heartbeat и базовые метрики (CPU/MEM/DISK/LOADAVG)
  - Конфиг через env vars

## Потоки данных

1. Agent отправляет heartbeat в `POST /api/v1/heartbeats`
2. Agent отправляет метрики в `POST /api/v1/metrics`
3. API валидирует, сохраняет в БД
4. Оценка алёртов (MVP) вызывается вручную через `POST /api/v1/alerts/evaluate` (или кнопкой в UI)

## Важные детали текущего MVP

- **Авторизация API**: все `/api/v1/`* требуют `X-Api-Key`; список ключей задаётся `API_KEYS`.
- **UI и безопасность**:
  - `UI_ENABLED=true` включает роуты `/ui`
  - `UI_REQUIRE_API_KEY=true` включает проверку `X-Api-Key` для `/ui`
- **Алёртинг (MVP)**:
  - `POST /api/v1/alerts/evaluate` синхронно считает среднее значение метрики по окну (`window_seconds`) и создаёт события `alert_events` со статусом `firing`
  - Дедупликации/состояния “одно событие на правило+сервер” пока нет: при каждом запуске проверки могут создаваться новые события
  - Чистка метрик по ретеншну выполняется там же (значение `METRIC_RETENTION_DAYS`)

## Нефункциональные требования (для “серьёзного уровня”)

- **Надёжность**: ретраи у агента, idempotency ключи для батчей (в следующих спринтах)
- **Безопасность**: секреты в env/secret store; ограничение ключей; аудит
- **Наблюдаемость**: структурированные логи; метрики API; трассировка (OTel)
- **Производительность**: батч-инжест метрик, партиционирование таблиц по времени
- **Эксплуатация**: Docker/K8s, миграции при старте, healthchecks
